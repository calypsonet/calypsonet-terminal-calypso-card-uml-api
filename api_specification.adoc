== Abstract

This document is the official technical specification of the **{spec-name}** standardised
by the **{organization}** ({short-name}).
It defines, in a language-agnostic way, the interfaces, classes, enumerations, exceptions, structural
relationships and behavioural requirements that any conforming implementation of the {spec-name} MUST satisfy.

The {spec-name} is the *application-facing* surface used by terminal applications to operate Calypso transit and
ticketing cards. It builds on top of the *Terminal Reader API* ([CNA-TR-API]) and delegates every cryptographic
operation to a symmetric ([CNA-TCCS-API]) or asymmetric ([CNA-TCCA-API]) crypto module.

== Introduction

=== Purpose

The {spec-name} defines the public surface used by terminal applications to:

* select a Calypso card through a [CNA-TR-API] selection scenario enriched with Calypso-specific commands;
* operate read-only transactions without involving a crypto module (*free* transaction);
* operate fully authenticated transactions using a *symmetric* crypto module ([CNA-TCCS-API]) -- either in the
  *regular* mode (compatible with every Calypso product) or in the *extended* mode (additional features only
  available on Calypso Prime Extended);
* operate fully authenticated transactions using an *asymmetric* crypto module ([CNA-TCCA-API]) in *PKI* mode;
* expose a dynamic view of the card (`CalypsoCard`) updated throughout the transaction.

=== Scope

This specification covers:

* the factory used to instantiate the public types of the API (`CalypsoCardApiFactory`);
* the data model of a Calypso card (`CalypsoCard`, `ElementaryFile`, `FileData`, `FileHeader`, `DirectoryHeader`,
  Stored Value log records);
* the selection extension (`CalypsoCardSelectionExtension`);
* the family of transaction managers (Free, Secure Regular, Secure Extended, Secure PKI);
* the *symmetric* and *asymmetric* security setting carriers;
* the *Stored Value* operations and *Search Record Multiple* support;
* the SPIs implemented by *crypto modules* to plug into the secure transaction managers;
* the family of exceptions raised during a Calypso transaction.

The following topics are *out of scope*:

* the on-the-wire APDU dialogue with the card (handled internally by the implementation);
* the cryptographic algorithms themselves -- only the SPI contract is normative;
* the on-the-wire transport between the terminal and any remote ticketing system.

=== Conformance

A software product conforms to this specification if and only if:

. it implements every interface and class defined in <<sec_specification>> with the operations and semantics
  prescribed in this document,
. it raises exceptions exclusively of the types defined in <<sec_exceptions>> for the situations described,
. it preserves the structural and behavioural relationships described in <<sec_architecture>>.

Throughout this specification, the key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, **RECOMMENDED**,
**MAY** and **OPTIONAL** are to be interpreted as described in **RFC 2119** and **RFC 8174** when, and only when,
they appear in all capitals.

In conformance with RFC 2119, **SHALL** is equivalent to **MUST**; this specification uses **MUST** exclusively in
order to avoid ambiguity.

|===
| Term              | Definition

| Secure Session    | Authenticated and integrity-protected exchange between the terminal and the card.

[[type_CalypsoCard]]
==== CalypsoCard

[cols="1h,4", grid=rows, frame=ends]
|===
| Kind     | Interface
| Package  | `calypso.card.card`
| Extends  | `IsoSmartCard` ([CNA-TR-API])
| Purpose  | Dynamic view of the card's content, updated from selection to the end of the transaction.
|===

A `CalypsoCard` carries: application identification (revision, class, DF name, serial number, ATR, issuer), the
indication of optional features (Stored Value, PIN, Rev 3.2 mode, ratification management), the management
information of the modification buffer, the invalidation status and the files / counters / SV data read or
modified during the transaction.

===== Identification operations

[cols="1h,3", grid=rows, frame=ends]
|===
| `getProductType() -> ProductType`        | Returns the card product type (`PRIME_REVISION_1` / `PRIME_REVISION_2` / `PRIME_REVISION_3` / `LIGHT` / `BASIC` / `UNKNOWN`).

| `isDfInvalidated() -> boolean`           | Tells whether the current DF is invalidated.

[[sec_csnmin]]
[NOTE]
====
*`csnMin` combination rule.* When several `assignOpenSecureSessionMaxDuration(...)` or
`assignSvOperationMaxDuration(...)` calls are made with different `csnMin` values, each call defines a *range*
bounded by its `csnMin` and the immediately higher declared `csnMin` (or `+∞` for the highest threshold). For a
given card, the range to which its CSN belongs determines the applied bound. This mechanism allows the integrator
to introduce or tighten duration bounds progressively as new generations of cards (with higher CSNs) are issued.
====

  already prepared/opened._

| `prepareSvGet(svOperation: SvOperation, svAction: SvAction) -> T`
| Schedules an *SV Get* command. _Throws `UnsupportedOperationException`, `IllegalArgumentException`._

| `prepareSvReload(amount: integer, date: byte array, time: byte array, free: byte array) -> T`
| Schedules an *SV Reload* command using the supplied additional data. Amount range: `-8388608..8388607`. _Throws
  `IllegalArgumentException`, `IllegalStateException`, `SessionBufferOverflowException`._

| `prepareSvReload(amount: integer) -> T`
| Schedules an *SV Reload* command with the optional data fields set to zero.

| `prepareSvDebit(amount: integer, date: byte array, time: byte array) -> T`
| Schedules an *SV Debit* or *SV Undebit* command using the supplied additional data. Amount: `0..32767` for
  debit, `0..32768` for undebit.

| `prepareSvDebit(amount: integer) -> T`
| Schedules an *SV Debit* or *SV Undebit* command with the optional data fields set to zero.

| `prepareInvalidate() -> T`
| Schedules an *Invalidate* command. _Throws `IllegalStateException` if the card is already invalidated._

| `prepareRehabilitate() -> T`
| Schedules a *Rehabilitate* command. _Throws `IllegalStateException` if the card is not invalidated._

| `prepareChangeKey(keyIndex: integer, newKif: byte, newKvc: byte, issuerKif: byte, issuerKvc: byte) -> T`
| Schedules a *Change Key* command. *MUST be performed outside a secure session.* All KIFs/KVCs MUST be available
  in the crypto module. _Throws `UnsupportedOperationException`, `IllegalArgumentException`,
  `IllegalStateException`._
|===

===== Operations

[cols="1h,3", grid=rows, frame=ends]
|===
| `prepareEarlyMutualAuthentication() -> SecureExtendedModeTransactionManager`
| Requests to mutually authenticate the card and the terminal *before* the secure session is closed. The use of

| Requests to stop the encryption. NOTE: `prepareCloseSecureSession()` automatically stops the encryption.

[[sec_exceptions]]
== Exceptions

All exception types defined by this specification are *unchecked* (runtime). Communication-level errors with the
reader or the card are reported through the [CNA-TR-API] exceptions (`ReaderCommunicationException`,
`CardCommunicationException`, `InvalidCardResponseException`) and are *not* duplicated here.

[[type_CardSignatureNotVerifiableException]]
=== CardSignatureNotVerifiableException

Runtime exception (final). Indicates that the card has correctly closed the secure session but that the
authenticity of the session cannot be verified because the crypto module is no longer available (timeout,
network problem, etc.).

Constructors: `(message)`, `(message, cause)`.

[[type_CryptoException]]
=== CryptoException

Runtime exception (final). Indicates that an error occurred when computing a crypto operation.

Constructor: `(message, cause)`.

[[type_CryptoIOException]]
=== CryptoIOException

Runtime exception (final). Indicates a communication error with the crypto module.

Constructor: `(message, cause)`.

[[type_InconsistentDataException]]
=== InconsistentDataException

Runtime exception (final). Indicates inconsistent data: either APDU-exchange de-synchronisation, or a discrepancy
between data read in session vs out of session.

Constructor: `(message)`.

[[type_InvalidCardSignatureException]]
=== InvalidCardSignatureException

Runtime exception (final). Indicates that the card signature is incorrect. For symmetric-key transactions, this
typically happens when the *Digest Authenticate* or *SV Check* status word is `6988h`. For PKI transactions, this
simply means that the card signature is invalid.

Constructor: `(message)`.

[[type_InvalidCertificateException]]
=== InvalidCertificateException

Runtime exception (final). Indicates that a certificate failed validation (signature, validity period, issuer or
subject details, constraints, extensions, expiration, revocation).

Constructors: `(message)`, `(message, cause)`.

[[type_InvalidPinException]]
=== InvalidPinException

Runtime exception (final). Indicates that the provided PIN is invalid.

Constructors: `(message)`, `(message, cause)`.

[[type_SelectFileException]]
=== SelectFileException

Runtime exception (final). Indicates that file selection failed because the file was not found (status word
`6A82h`).

Constructor: `(message, cause)`.

[[type_SessionBufferOverflowException]]
=== SessionBufferOverflowException

Runtime exception (final). Indicates that the secure session cannot be performed atomically because the
modification buffer capacity is insufficient.

Constructor: `(message)`.

[[type_UnauthorizedKeyException]]
=== UnauthorizedKeyException

Runtime exception (final). Indicates that the card requires an unauthorised session key.

Constructor: `(message)`.

[[sec_behaviours]]
== Behavioural Requirements

. The `CalypsoCard` instance bound to a transaction MUST be a *dynamic view* of the card image and MUST be
  updated after every successful command. Failed write commands MUST NOT update the in-memory image.
. Operations marked with a *SECURITY WARNING* MUST NOT be used inside a secure session; implementations MUST
  raise `IllegalStateException` if invoked while a session is open.
. The merging of *Open Secure Session* with a possible *Read Record* command is enabled by default; the
  application MAY opt out via `SymmetricCryptoSecuritySetting.disableReadOnSessionOpening()`. When the pre-open
  mode is active, this optimisation MUST NOT be performed.
. The *PKI* mode (`SecurePkiModeTransactionManager`) MUST NOT be available unless the card declares
  `isPkiModeSupported() == true`.
. Communication errors at the reader, card or APDU level MUST be reported through the [CNA-TR-API] exceptions
  (`ReaderCommunicationException`, `CardCommunicationException`, `InvalidCardResponseException`); this
  specification does not duplicate them.
. Implementations MUST raise `SessionBufferOverflowException` instead of silently truncating a session when
  multiple-session mode is disabled and the modification buffer would overflow.
